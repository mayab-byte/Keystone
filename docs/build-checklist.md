# Keystone — צ'קליסט לשלב הבנייה וההשקה

> מסמך עבודה פנימי של BMF Studio. מרכז את כל מה שסוכם בשלב העיצוב אך שייך
> לשלב הבנייה/ההשקה: דרישות GSO, נגישות, טופס לידים, והחלפות placeholder.
> מה שכבר יושם בשלב העיצוב מסומן ✅ בתחתית המסמך.

---

## 1. החלפות placeholder לפני עלייה לאוויר (קריטי)

- [ ] טלפון אמיתי במקום `050-000-0000` (מוגדר במקום אחד: `app/shared.tsx` → `contact`)
- [ ] מספר וואטסאפ אמיתי במקום `972500000000` (אותו קובץ — מזין גם את הטופס וגם את כל הכפתורים)
- [ ] אימייל אמיתי במקום `office@keystone-fin.co.il`
- [ ] שם חברה רשמי + ח.פ. בעמוד מדיניות הפרטיות (`privacy/page.tsx` → `COMPANY`)
- [ ] שם רכז/ת נגישות אמיתי בעמוד הצהרת הנגישות (`accessibility/page.tsx`)
- [ ] מספרי רישיון (משווק פנסיוני / סוכן ביטוח) של שני השותפים — להציג בפוטר ובעמוד אודות
- [ ] אישור הלקוחות לנוסח ההמלצות והסיפורים במאמרים (דוד, לקוח הדירה, לקוחת ה-950K)
- [ ] הסרת `robots: { index: false }` מכל עמודי Keystone (כרגע מוגדר בכולם כי זה preview)
- [ ] העברה לדומיין אמיתי + עדכון כל הקישורים האבסולוטיים

## 2. טופס לידים — מעבר מ-WhatsApp-prefill ל-backend אמיתי

הטופס כרגע פותח וואטסאפ עם הודעה מוכנה (פתרון ללא שרת לשלב העיצוב).
בשלב הבנייה:

- [ ] Endpoint אמיתי (API route) שקולט את הפנייה + שליחה ל-CRM/מייל של הלקוח
- [ ] **תיעוד הסכמות דיוור**: לשמור timestamp + נוסח ההסכמה + IP לכל ליד
      (דרישת סעיף 30א לחוק התקשורת — חובת הוכחת הסכמה)
- [ ] ולידציה בצד שרת (שם, טלפון ישראלי, אימייל) — לא להסתמך רק על HTML5
- [ ] הודעות שגיאה/הצלחה נגישות: אזור `aria-live="polite"`, פוקוס לשדה השגוי
- [ ] הגנת ספאם (rate limit / honeypot — לא CAPTCHA ויזואלי שפוגע בנגישות)
- [ ] מנגנון הסרה מדיוור (unsubscribe) בכל הודעת מייל

## 3. GSO — תשתית שמכונות יכולות לקרוא (הדיברה השלישית)

- [ ] `robots.txt` שמתיר במפורש: GPTBot, ClaudeBot, PerplexityBot, Google-Extended, OAI-SearchBot, בוטים גנרטיביים נוספים
- [ ] `sitemap.xml` מעודכן ומקושר מ-robots.txt
- [ ] כל התוכן הקריטי ב-HTML סטטי (העמודים כבר Server Components — לוודא שנשאר כך; לבדוק עם `curl` שהתוכן נראה ללא JS)
- [ ] יעדי ביצועים: TTFB < 600ms, LCP < 2.5s במובייל
- [ ] CDN, lazy loading לתמונות שאינן above-the-fold (תמונת ההירו נשארת `priority`)
- [ ] מינימום סקריפטים של צד שלישי; שום סקריפט חוסם רינדור
- [ ] בלי פופאפים שחוסמים את התוכן הראשון

## 4. GSO — Schema / JSON-LD (הדיברה הרביעית)

- [ ] `Organization` על כל העמודים: שם, לוגו, כתובת, טלפון + `sameAs` (פייסבוק, לינקדאין, דירקטוריות)
- [ ] `Person` לשלומי אחלופי ולשלומי פרידמן (author bios כבר קיימים בתוכן)
- [ ] `Article` לכל מאמר בלוג: `author`, `datePublished`, `dateModified`, `headline`, `image`
      (השדות כבר קיימים ב-`articles.ts` — נשאר רק להזרים ל-JSON-LD)
- [ ] `FAQPage` לכל מאמר (ה-FAQ כבר כתוב בכל מאמר) ולעמוד הבית
- [ ] `HowTo` למאמרים עם שלבים ממוספרים (מאמר הדירה ומאמר המס)
- [ ] בדיקת Rich Results Test של גוגל על כל עמוד מרכזי
- [ ] עקביות NAP: פרטי הארגון ב-schema זהים לכל מקום אחר ברשת

## 5. GSO — ארכיטקטורה סמנטית (הדיברה החמישית)

- [ ] מבנה hub-and-spoke: עמוד hub לכל נושא רחב (מיסוי השקעות / פנסיוני / ביטוח / פרישה) עם spokes של מאמרים — שלושת המאמרים הקיימים הם הבסיס ל-hub "מיסוי השקעות"
- [ ] URL היררכי בדומיין האמיתי: `/blog/<slug>` (כבר כך) — לשקול `/blog/tax/<slug>` כשיהיו אשכולות
- [ ] בלי דפים יתומים: כל עמוד מקושר מלפחות 2 עמודים אחרים (כרגע: כל מאמר מקושר מהבלוג + מעמוד הבית ✅ — לשמור על זה בהוספת עמודים)
- [ ] קישורים פנימיים בין מאמרים קשורים (spoke↔spoke, spoke↔hub)

## 6. GSO — תוכן שוטף (דיברות 1, 2, 7, 8)

- [ ] מיפוי 20–50 פרומפטים אמיתיים בתחום (Reddit, פורומים פיננסיים, קבוצות פייסבוק של משקיעים)
- [ ] כל מאמר חדש: כותרת-שאלה, תשובה ישירה ב-100 המילים הראשונות, TL;DR, FAQ של 5–10 שאלות (התבנית הקיימת ב-`articles.ts` כבר אוכפת את זה)
- [ ] כל עמוד מרכזי מכיל לפחות 3 מתוך 5 סוגי בלוקים: Definition / Comparison / Explainer / Fact Cluster / FAQ
- [ ] מספרים וסטטיסטיקות — תמיד עם מקור ותאריך
- [ ] ציטוטי מומחים עם שם מלא ותפקיד; קישורים יוצאים למקורות סמכותיים (רשות שוק ההון, רשות המסים, בנק ישראל)

## 7. GSO — הפצה ומדידה (דיברות 9, 10)

- [ ] רישום בדירקטוריות מקצועיות רלוונטיות בפורמט עקבי
- [ ] נוכחות באזורי Trigger: תשובות בקבוצות/פורומים רלוונטיים, לינקדאין של שני השותפים
- [ ] בניית רשימת 30–50 פרומפטים מרכזיים למעקב
- [ ] הרצה דו-שבועית על ChatGPT / Claude / Perplexity / Gemini ותיעוד: Inclusion Rate, Citation Rate, Position in Answer, Cross-GSA Coverage

## 8. נגישות — השלמות לשלב הבנייה (ת"י 5568 / AA)

- [ ] מינוי רכז/ת נגישות בפועל ועדכון ההצהרה בפרטים אמיתיים
- [ ] בדיקת קורא מסך מלאה (NVDA + מובייל VoiceOver/TalkBack) על כל העמודים
- [ ] בדיקת ניווט מקלדת מלאה על כל flow (כולל הטופס והתפריט במובייל)
- [ ] בדיקת הגדלת טקסט ל-200% וזום 400% ללא אובדן תוכן
- [ ] הודעות שגיאה בטופס נגישות (aria-live, קישור פוקוס לשדה) — תלוי ב-backend מסעיף 2
- [ ] אם יוטמע סרטון בהירו: כפתור עצירה נגיש, ללא אודיו אוטומטי, כתוביות אם יש דיבור, ולכבד prefers-reduced-motion
- [ ] בדיקה עם כלי אוטומטי (axe / Lighthouse a11y) + בדיקה ידנית לפני השקה
- [ ] תפריט המבורגר נגיש במובייל (כרגע הניווט מוסתר במובייל — קיים רק בדסקטופ; להוסיף בשלב הבנייה)

## 9. מה כבר יושם בשלב העיצוב ✅

- ✅ ניגודיות AA בכל צמדי טקסט/רקע (כולל טקסט כהה על כפתורי הגרדיאנט, teal כהה `#007487` לטקסט קטן על לבן)
- ✅ Skip link "דילוג לתוכן הראשי" + `<main id="main">` בכל העמודים
- ✅ פוקוס גלוי בצבע שעובר 3:1 גם על רקע לבן וגם על שחור
- ✅ טופס לפי הספק: שם מלא + טלפון + אימייל + הסכמת דיוור, כולם חובה ומסומנים `*`, שדות אטומים (ללא שקיפות), ולידציית טלפון (minLength 9 + pattern ישראלי), נוסח ההסכמה עם קישור למדיניות פרטיות ב-target="_blank"
- ✅ עמוד מדיניות פרטיות + עמוד הצהרת נגישות, מקושרים מהפוטר בכל העמודים
- ✅ בלוג + 3 מאמרים במבנה GSO: כותרות-שאלה, תשובה ישירה ראשונה, TL;DR, בלוקים אטומיים (הגדרה/השוואה/שלבים/עובדות), FAQ, author bio, datePublished/dateModified, טבלת השוואה נגישה (caption + scope)
- ✅ סקשן מאמרים בעמוד הבית + קישורים פנימיים (כל מאמר מקושר מ-2 מקומות)
- ✅ רספונסיביות מלאה + סרגל CTA דביק במובייל (44px+) + safe-area
- ✅ prefers-reduced-motion מכובד גלובלית
- ✅ alt לתמונות משמעות, aria-hidden לדקורטיביים, מבנה כותרות היררכי
